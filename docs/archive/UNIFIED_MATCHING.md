# 统一显示文本匹配

## 查找顺序

所有现有显示与测量 Hook 继续调用同一查找入口。输入保护和中英开关的优先级不变，不修改源控件、节点名称、参数值或路径。

1. 原文精确匹配。
2. 保留已有菜单助记符 `&`、末尾修改标记 `*` 处理，再精确匹配；输出恢复修改标记。
3. 规范化匹配：Unicode 大小写折叠、首尾及连续空白整理、全角拉丁字母和数字转半角。不会统一数学运算符。
4. 名称变体匹配：仅长度不超过 64、由拉丁字母及空格/下划线/连字符组成的显示文字，合并分隔符后至少有 3 个字母。例如 `Rough_Glass`、`roughglass`、`Rough-Glass` 对应 `Rough Glass`。这是字符形态限制，不是新增的材质控件类型识别。
5. 现有显式占位符模板：`{name:int}`、`{name:number}`、`{name:percent}`；保留捕获值原貌和模板验证，不自动学习任意通配符。模板固定部分仍按原文匹配。
6. 自动相似度匹配。
7. 未命中时由原绘制函数显示英文；开发捕获模式保持原行为。

规范化键或名称变体键对应不同译文时，拒绝这个非精确匹配，不继续猜测。不同来源但译文相同可以合并。原文精确命中不受影响。

## 自动相似度

使用完整文本、保留顺序的 Levenshtein 编辑距离：

`score = 100 × (1 − distance / max(length1, length2))`

默认最高分严格大于 90，且比不同译文的第二候选至少高 5 个百分点。同译文候选不会互相惩罚。相似度不代表语义准确率，仍需要真实 UI 测试。

仅自动处理规范化后 6–192 个字符、至少 6 个拉丁字母，且其他字符只有数字、空格、下划线或连字符的显示文字。路径分隔符、表达式符号、模板占位符等不进入该级。短词仍可精确或规范化匹配。

数字序列和数字前的负号必须相同。按空格/下划线/连字符分词检查关键方向及开关词（例如 enable/disable、on/off、not/no、input/output、min/max）；关键词序列不同则排除候选。这是有限的语义保护，并非自然语言理解。

## 配置

插件目录的 `HoudiniChinese.ini`，重启生效：

```ini
[Matching]
fuzzyEnabled=true
threshold=90
margin=5
```

`threshold` 支持 90–99，`margin` 支持 1–10；非法数值读取时使用默认值。关闭 `fuzzyEnabled` 只关闭相似度级，精确、规范化、名称变体和模板仍工作。旧配置缺少这些键时采用默认值；修改快捷键保留匹配设置。

## 性能与限制

加载词典时建立不可变规范化索引、名称索引和三字符片段倒排索引。查询先根据长度、共享片段数量和关键差异筛选候选，再进行带状编辑距离计算。保留原有线程本地 256 槽结果缓存，包含未命中缓存。不添加后台扫描或定时器。

索引在原有后台词典加载阶段构建；配置包含 Qt 快捷键对象，必须等 QApplication 初始化后在主线程读取，在挂载显示 Hook 前设置匹配选项，不能移到后台提前读取。

单次查询最多访问 200,000 个倒排项、评估 8,192 个候选和 1,000,000 个距离矩阵单元；预算不足返回未命中，不根据部分候选作决定。因此复杂或极度重复的词典可能保守漏配。

本次 53,543 条正式词典测试：索引约 148 ms；200 次未缓存查询约 27 ms（两种测试文本重复查询，包含命中与未命中，不能等同于实际 Houdini 总 CPU 占用）。规范化与名称索引共发现 405 个冲突键，可能包含重复涉及同一组词条的两类键。

## 验证

`tests/run.bat` 包含名称变体、全角形式、严格 90% 边界、数字/负号/开关词、歧义、禁用开关，以及随机增删改文本对完整距离算法的对照验证。完整词典冲突键输出到 `build/tests/matching-conflicts.txt`。

真实绘制适配器测试覆盖精确优先、带修改标记的模糊命中、输入保护与关闭汉化后的原文回退；原有 QML、宽度恢复、Hook 和 Python 回归测试保持通过。

当前构建验证目标为 Houdini 22.0.368 / Qt 6.8.3 / Windows x64；未据此扩大旧版 Houdini 或 Qt 5 支持范围。

最终测试构建位于 `build/out-unified-matching-v2`。真实启动的 20 秒报告确认词典就绪、汉化启用、UI_Look::draw 已挂载且观察到 733 次调用，标准错误日志为空。该记录证明启动及绘制入口工作，不代替用户对具体界面的视觉验收。
