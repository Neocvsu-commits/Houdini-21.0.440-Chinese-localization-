## 后台性能复核

- 空闲期间按钮归属不再每秒检查。初始化最多 30 次；成功或预算耗尽停止，之后靠事件唤起。
- 按钮定位只在布局变化后最多跟随 12 帧，每帧 16 ms；没有恢复 500 ms 位置轮询。
- 模块扫描启动阶段每 2 秒，60 秒后每 15 秒一次。仍有模块枚举/身份读取成本；已知成功模块不会每次重写导入表。
- QML 初始化全量刷新由 `g_quickTextRefreshScheduled` 限制为一次，不是每次模块扫描都遍历界面。
- 本次新增 QPointer 只用于这条初始化刷新路径，不为每次文字绘制增加弱指针队列。
- 中文查词使用每线程有界缓存和启动后只读词典；英文且未采集时提前返回，词典未命中且未采集时跳过编辑调用栈检查。
- 未知原生绘制路径在命中翻译时仍可能检查调用栈；这部分是后续性能优化点，不能为了速度直接移除输入保护。
- 诊断默认关闭；审核启动包只在有限的采样窗口内开启计数。上一轮独立微基准见 CORE_AUDIT_2026-09-06.md，不能把纳秒级缓存结果当作整个 Houdini 的 CPU 占用。
- 本轮没有完成同场景“无插件/有插件”的长时间 CPU、帧率和内存对照，因此不宣称整体性能提升比例或零后台开销。

## 仍需区分的边界

1. HDK/Qt 身份相同不证明 Houdini 私有类布局与调用语义一致。当前仅有 22.0.368 的实际宿主验证；其他 daily build、Qt 5 和旧版不能标为已兼容。
2. 缺符号、缺挂载和词典缺词是不同状态；没有任何单次审核能证明所有私有 UI 都有翻译覆盖。保留入口清单和可选调用诊断，不擅自缩减 Hook。
3. Hook 使用宿主线程事务和原生地址访问。此次验证了 C++ 异常回滚，但没有做所有第三方插件并发改页权限、极端线程竞争、全进程内存耗尽或长时间压力测试。
4. UI_Look 延迟补挂载仍是独立包显式开启的实验选项；标准包没有擅自改成默认开启。
5. 用户独立修改的两个附加词典保留原内容，在本次保存时一并提交；backups 保留在本地。工作区无跟踪的 `tools/run_new_houdini_test.bat` 含关闭全部 Houdini 的命令，本轮没有执行、提交或修改它。
